# 安全模型

## 需要保护的资产

- 仓库源码与 Git 历史；
- 凭据和外部服务配置；
- 验证结果的完整性；
- 任务范围与用户意图；
- 运行报告与失败知识；
- 开发者工作站和 CI Runner。

## 已覆盖的威胁

- 过期或无关计划授权新任务；
- 将只读上下文、反向依赖或同步域误当成写入授权；
- 写入超出任务明确声明的 `writeTargets`；
- 分支、提交或基线发生漂移；
- 危险 shell 与 Git 操作；
- 删除测试、提交运行数据、锁文件漂移和公共 API/客户端不同步；
- 凭据、高熵密钥、私钥、本机路径和发布许可证缺失；
- 高危或严重依赖漏洞；
- 未完成验证便结束任务或提交。
- 候选分支替换 Judge、策略、Auditor 或受保护对抗语料；
- 缺失、跳过、旧状态字符串或不可验证证据被提升为 PASS；
- 跨运行证据混用、并发丢写、缓存污染和候选树/交付树不一致；
- 命令通过 shell 插值、环境继承、网络访问、输出或可写路径逃逸边界；
- 复用另一仓库的 CI 观测、分支保护状态或正式证明。

## 强制层

1. **PreToolUse：** 验证活动租约，只允许任务明确声明的精确写入目标，并拒绝可识别的危险或越界操作。
2. **PostToolUse：** 将工具调用后的 Git 可见副作用与绑定影响报告比较。
3. **Stop / Closeout：** 停止时自动执行 Guard、计划验证、第二次 Guard、报告和失败处理；任何一步失败都会阻止结束。
4. **安全扫描器：** 检查当前文件、可选 Git 历史、依赖、本机路径和许可证，不记录密钥原文。
5. **Docker 沙箱：** 可选禁网、只读挂载、移除 capabilities、禁止提权并限制资源。
6. **安全执行器：** 只接受结构化命令，默认禁网并限制环境、资源、输出、进程数和可写目录。
7. **独立 Auditor：** 从内容寻址证据重算结果；执行器、候选分支和手写报告都不能自行签发正式 PASS。
8. **CI 双重身份：** 受保护基线提供 Judge，候选 checkout 只作为被评估对象；两者的提交和树身份均被密封。

## 不提供的保证

- ScopeLatch 不是内核、虚拟机或 Hypervisor 边界。
- Hook 匹配依赖智能体平台产生受支持的工具事件。
- 正则表达式和命令解析无法识别所有可能的写入机制。
- 基于 Git 的 Guard 无法观察仓库外副作用或其快照模型不可见的变化。
- 依赖扫描依赖本机包管理工具和外部漏洞数据源。
- 上下文排序仍是启发式过程，高风险任务需要人工复核。
- Shadow 工作流是观测通道，不是合并许可；正式工作流仍依赖 GitHub 外部强制策略。
- 本仓库当前没有满足 H8 的 20 次/7 天窗口，也没有已观测的 H9 外部强制策略，因此正式资格保持阻断。

## 安全部署建议

- 启用 Hook 前审查并信任 `.codex/config.toml`。
- 对配置和工作流变更执行代码审查。
- 将 `Harness v4 Formal Attestation` 配置为受保护分支 required check 前，先完成 H8/H9 外部观测。
- 让 ScopeLatch 运行状态保持忽略和私有。
- CI 使用最小权限令牌，默认只读。
- 所有 checkout 均禁用凭据持久化；候选工作区不得保留 GitHub 临时令牌。
- 不可信代码使用 Docker 沙箱或更强隔离。
- 打标签或分发前运行 `public-release` 安全扫描。
- 凭据一旦泄露应立即撤销，不能只依赖删除最新文件。
