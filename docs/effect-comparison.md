# ScopeLatch 真实效果与演进对照

这份对照不使用主观打分，也不声称“开发效率提升了某个百分比”。现有证据能够可靠回答的是：**ScopeLatch 从没有仓库控制，到具备 17 项可核验控制能力；测试文件由初版的 8 个增加到 26 个，静态断言出现次数由 86 增加到 452，并在真实项目中持续产出 Guard、验证和收尾证据。**

## 结论先行

| 阶段 | 可核验控制项 | 引擎模块 | 测试文件 | 断言出现次数 | 主要变化 |
|---|---:|---:|---:|---:|---|
| 未使用 Harness | 0 / 17 | 0 | 0 | 0 | 没有计划、范围守卫、验证编排或审计证据 |
| 初版项目感知原型 | 5 / 17 | 14 | 8 | 86 | 加入上下文、影响分析、验证图、Diff Guard 和写前 Hook |
| 项目实测优化 | 8 / 17 | 17 | 12 | 179 | 加入有限修复、报告和失败知识处理 |
| Harness Engine V3.2 | 14 / 17 | 27 | 24 | 332 | 加入写后副作用检查、会话绑定、权威源码、安全扫描和 Docker 沙箱 |
| Harness Engine V3.3 | 15 / 17 | 27 | 25 | 377 | 所有主执行路径统一为强制收尾，提交前必须存在完整证据 |
| ScopeLatch 3.4.0 | 17 / 17 | 27 | 26 | 452 | 只允许精确 `writeTargets`，停止时自动执行完整收尾 |

从初版到 3.4.0，引擎模块数增加 `92.9%`，测试文件数增加 `225%`，断言出现次数增加 `425.6%`。这些数字只代表实现与验证覆盖规模，不等同于缺陷率下降或开发速度提升。

## 数据如何得到

1. **固定历史快照：** 使用 Git 提交树读取六个时间点，不依赖当前工作区文件。
2. **模块数：** 统计提交中 `harness/lib/*.mjs`。
3. **测试文件数：** 统计提交中 `harness/tests/*.test.mjs`。
4. **断言出现次数：** 对测试文件中的 `assert.equal`、`assert.deepEqual`、`assert.ok`、`assert.match`、`assert.throws` 等调用做静态计数。它不是独立测试用例数。
5. **能力判定：** 根据实现文件存在性和关键策略是否实际进入代码判断，不根据 README 宣传文字判断。
6. **运行记录：** 只聚合 `.harness/runs` 中可解析的 JSON 和报告文件，不读取业务数据或提示内容。
7. **当前版本：** 3.4.0 的 26 个测试文件、公开发布安全扫描和 Docker 沙箱均由 [GitHub Actions #29971645147](https://github.com/zzh3110296407-cmd/ScopeLatch-Agent-Engineering-Harness/actions/runs/29971645147) 实际通过。

原始聚合数据保存在 [`docs/evidence/scope-evolution-baseline.json`](evidence/scope-evolution-baseline.json)。公开仓库每次 CI 都会重新计算 3.4.0 的模块、测试、断言和 17 项能力标志，防止表格与代码悄悄漂移。

## 复现方式

公开仓库可直接验证当前版本：

```bash
npm run evidence:verify
npm test
node harness/cli.mjs security --profile public-release
```

维护者拥有原项目 Git 历史时，还可以复核全部历史提交和运行档案下限：

```bash
node scripts/verify-effect-comparison.mjs --private-source "<source-repository-path>"
```

## 尚未声称的效果

- 没有可信的同任务随机对照实验，因此不声称节省了多少开发时间。
- 没有统一标注“逃逸缺陷”，因此不声称缺陷率降低了多少。
- 历史运行档案来自单一复杂项目，能够证明长期使用和控制链执行，但不能自动外推到所有仓库。
- ScopeLatch 仍不是操作系统级沙箱；不可信代码应继续使用容器、虚拟机或更强隔离。

后续若要量化效率，应预先注册同一任务集、随机分配“无 Harness / ScopeLatch”条件，并记录任务完成时间、越界写入、首次验证通过率、修复轮数和人工审查缺陷。得到这类数据后再发布效率百分比，才具有统计可信度。
